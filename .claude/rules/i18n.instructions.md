# Internationalisation (i18n)

## Frontend

- Every user-visible string goes through vue-i18n (`frontend/src/locales/`). No raw text in templates.
- Keys are named by feature/epic (e.g. `ag.resolution.title`), never source text as key.
- Generic labels (actions, field labels, common statuses) always reuse the existing `common.*` key — the same text must never be redefined under another key. Exception: dynamic enum namespaces (e.g. `tasks.statuses.*`, `contracts.statuses.*`).
- `common.*` is reserved for **general semantics only**: field labels (`title`, `description`, `address`…), generic CRUD actions (`save`, `cancel`, `delete`…), generic states (`pending`, `overdue`…), transverse empty/error states. A key whose semantics belong to a single feature/page **must stay in its own namespace** (e.g. `nav.dashboard`, `budget.closeExercise`, `auth.newPassword`) — except if its text duplicates a `common.*` value.

### Anti-duplicate procedure (text wins over semantics)

The classification rule above decides where a *new* key belongs, but **duplication is decided by value, not by key**: a feature-namespaced key whose text is byte-identical to an existing `common.*` value is a duplicate and must be removed — point the usage at the `common.*` key instead. "Common" here means ordinary vocabulary (a field label, a status word, an action), not "shared by N features".

Concretely, before adding or keeping a key outside `common.*`:

1. Search the locale file for the exact string: if it already exists under `common.*`, reuse that key and delete the duplicate.
2. If it exists under another feature namespace with the same text, promote the shared text to `common.*` (new key if none fits) and update all usages.
3. Only dynamic enum namespaces (`*.statuses.*`, `*.priorities.*`, filter-tab labels tied to an enum value…) may keep feature-local values.

Check for duplicates mechanically when touching locales, e.g. a one-liner that lists every non-`common` value that also exists under `common.*`.

## Backend

- The backend never returns a displayable hard-coded error message: it returns stable error codes under the `errors.*` namespace, translated on the frontend via vue-i18n.
- Any new error code must have a translation in every locale.

## Local formats

- Dates, numbers and amounts are formatted with `Intl` using the `fr-FR` locale by default (the application is French).
- Amounts are stored as integer cents in the backend, formatted on the frontend.
